# Single-panel catalog → detail + centered create dialog

Single-panel variant (also generated by `panel scaffold`) for cases where catalog and detail share one panel and one
entry. For most multi-column catalog + detail applications, prefer the
[two-entry catalog → detail template](../two-entry-catalog-detail/README.md) so the detail view has its own clean URL
and browser back stack.

- **Catalog view**: `<page-header>` with a primary `+ New …` button (`@click="startCreate"`), and a full-width
  `ObjectList` with outer page gutter (`--page-gutter`).
- **Detail view**: clicking a row hides the catalog and renders a single-row `<page-header>` (`← Back | <Title> | [Delete] [Discard] [Save]`) wired to `usePanelFormDraft("form")` and `usePanelBack` (browser Back, Escape, and unified
  unsaved-changes confirmation). Content renders equal-height rounded cards in a two-column `@container` grid that
  collapses to one column below `850px`.
- **Create dialog**: clicking `+ New …` sets public state `creating: true, selected: null` and opens a centered
  `<sdk-dialog>` hosting the same `ObjectForm` member (`config.actions: "create-only"` shows Cancel/Create in the
  dialog while edit mode saves from `<page-header :draft="formDraft">`).

## Check and register directly

```sh
template="$SKILL/references/templates/catalog-detail-dialog"
node "$SKILL/ontomato.mjs" panel check "$template"
node "$SKILL/ontomato.mjs" panel register "$template"
```

Open `/applications/app-template-catalog-detail/manage` (or generate a customized copy for any type with
`node "$SKILL/ontomato.mjs" panel scaffold <type-id> ./my-panel --id app-my-panel`).

## Adapting this template to another type

1. **Inspect the type**: run `node "$SKILL/ontomato.mjs" panel type <type-id>` and update `TYPE` in `panel.mjs`,
   `objectType` / `type` / `data` / `operation` in `panel.json`, and IDs/paths in `registration.json`. For customer
   ontology classes, bind the platform's generic read functions parameterized by class (`list` / `record` shown by
   `panel type <class>`).
2. **Configure table columns**: add `config.columns` on the `list` `ObjectList` member for multi-column tables (see
   `CODE.md#configure-an-official-list-or-summary`).
3. **Add a header Delete button**: declare a `remove` member on `manifest.members` and place `<projection slot="remove">`
   inside the detail `<page-header>`'s `#actions` slot:

   ```json
   "remove": {
     "component": "OperationButton",
     "operation": "<owner.delete>",
     "target": "selected",
     "config": { "label": "Delete", "type": "danger", "plain": true, "icon": "trash" }
   }
   ```

4. **Multi-locale labels (optional)**: when shipping a panel in multiple locales, keep UI text in `panel.json`'s
   `content.messages` (for example `"en"` and `"zh-CN"`). Single-locale panels may write UI text directly in
   `panel.html` / `panel.mjs` or use `content.messages`.
5. **Form controls from the owner**: `ObjectForm` automatically shows word counters when the owner schema declares
   `maxLength`, and disables dependent select fields when the owner declares `disabledWhenEmpty` / upstream
   `source.params`. Keep validation and field rules on the owner side.
