# Panel page templates

Pick the template that matches the page's natural shape instead of forcing every page into one layout. Multi-column
tables stay full width — do not squeeze them into a split list-detail pane.

## Universal baselines

1. **One primary action per action bar; danger semantics for delete.** Highlight at most one primary button in each
   independent action area (`<page-header>`, dialog footer, or form bar). Use `type: "danger"` and platform confirmation
   for destructive actions.
2. **Never silently lose unsaved edits.** Bind `<page-header :draft="formDraft">` with `usePanelFormDraft("form")` so
   Save, Discard, and the unsaved indicator follow the platform standard. When a detail view lives inside the same panel
   (instead of its own entry) or has a custom Back button, wire `usePanelBack` so Back and Escape share the platform's
   unsaved-changes confirmation.
3. **Clear states and container-width layout.** Distinguish empty, no search match, forbidden, and load error (with
   retry). Use standard CSS `@container` queries and container-relative sizing rather than `window.innerWidth` so the
   panel adapts cleanly both full-width and beside a conversation.

## Available templates

| Page shape | When to use | Template |
| --- | --- | --- |
| **Two-entry catalog → single-row `<page-header>` detail + centered create dialog** *(recommended)* | Multi-column catalogs or records whose detail needs full width (two-column cards, forms, code, or sub-tables) and its own clean URL / browser history. | [two-entry-catalog-detail/](two-entry-catalog-detail/README.md) |
| **Single-panel catalog → detail + centered create dialog** | Same full-width catalog + detail + create dialog when you prefer one panel and one entry. | [catalog-detail-dialog/](catalog-detail-dialog/README.md) (also generated by `panel scaffold`) |
| **Persistent left list/tree + right detail/editor** | Lightweight left items (title + short subtitle, or hierarchy tree) for rapid side-by-side browsing, review, or editing. | Compose with a standard CSS two-column grid (`@container` collapsing to one column when narrow), `<page-header>`, `ObjectList`, `ObjectSummary`, and `ObjectForm` (`CODE.md`). |
| **Canvas-centered graph** | Node-and-relation graph exploration or visual modeling (`ObjectGraph` / `OntologyGraph` filling the content box). | Follow [graph wiring in `CODE.md`](../panel-authoring/CODE.md#connect-a-graph-and-its-relations). |
