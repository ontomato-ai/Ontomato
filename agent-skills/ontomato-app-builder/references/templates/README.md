# Panel page templates

Pick the template that matches the page's natural shape instead of forcing every page into one layout. Multi-column
tables stay full width — do not squeeze them into a split list-detail pane.

## Universal baselines (all templates)

1. **One primary action per action bar; danger semantics for delete.** Highlight at most one primary button in each
   independent action area (page header, detail header, or dialog footer). Use `type: "danger"` and platform
   confirmation for destructive actions.
2. **Never silently lose unsaved edits.** Wire `usePanelBack` so browser Back, Escape, and in-page back buttons run the
   host's unified unsaved-changes confirmation.
3. **Clear states and container-width layout.** Distinguish empty, no search match, forbidden, and load error (with
   retry). Respond to the panel's own container width (`@container` or `usePanelNarrow`), never `window.innerWidth` or
   CSS viewport units (`vh`/`vw`/`dvh`), and reserve bottom scroll room (`calc(var(--page-content-gap) + 56px)`) for
   the floating page composer.

## Available templates

| Page shape | When to use | Template |
| --- | --- | --- |
| **Full-width catalog table → full-width detail + centered create dialog** | Multi-column catalogs or records whose detail needs full width (two-column cards, forms, code, or sub-tables). | [catalog-detail-dialog/](catalog-detail-dialog/README.md) (also generated by `panel scaffold`) |
| **Full-width table + inline row actions + modal edit/create** | Operational ledgers with frequent toggles or per-row actions (`listColumn` + `OperationButton` / `listRowDetail`) that do not need a full-page detail view. | Compose from `ObjectList` (`config.columns` + `listColumn`), `sdk-dialog`, and `ObjectForm` (`CODE.md`). |
| **Persistent left list/tree + right detail/editor** | Lightweight left items (title + short subtitle, or hierarchy tree) for rapid side-by-side browsing, review, or editing. | Compose with normal CSS two-column grid + `usePanelNarrow` + `usePanelBack` (`CODE.md`). Dedicated starter template will be added once the reference page is verified. |
| **Canvas-centered graph** | Node-and-relation graph exploration or visual modeling (`ObjectGraph` / `OntologyGraph` filling the content box edge-to-edge). | Follow [graph wiring in `CODE.md`](../panel-authoring/CODE.md#connect-a-graph-and-its-relations). Dedicated starter template will be added once the reference page is verified. |
