# Panel page templates

Pick the template that matches the page's natural shape instead of forcing every page into one layout. Multi-column
tables stay full width — do not squeeze them into a split list-detail pane. Every template below uses flat named query
parameters (`panelAddress`), read-only projection outputs (`usePanelOutput`), rowless slots, container queries
(`@container`), and keeps dialog/edit states non-`deepLink`.

## Universal baselines

1. **One primary action per action bar; danger semantics for delete.** Highlight at most one primary button in each
   independent action area (`<page-header>`, dialog footer, or form bar). Use `type: "danger"` and platform confirmation
   for destructive actions.
2. **Never silently lose unsaved edits.** Bind `<page-header :draft="formDraft">` with `usePanelFormDraft("form")` so
   Save, Discard, and the unsaved indicator follow the platform standard. When a detail view lives inside the same panel
   (instead of its own entry) or has a custom Back button, wire `usePanelBack` so Back and Escape share the platform's
   unsaved-changes confirmation.
3. **Clear states and container-width layout.** Distinguish empty, no search match, forbidden, and load error (with
   retry). Use standard CSS `@container` queries and container-relative sizing rather than `window.innerWidth` so the
   panel adapts cleanly both full-width and beside a conversation.

## Clean reference templates (recommended starting points)

| Page shape | When to use | Template |
| --- | --- | --- |
| **Catalog + side-by-side detail cards** (`platform:Relationship`) | Full-width catalog table (`ObjectList` + `filteredCount`) navigating to a two-column detail page (`ObjectHeader` + `ObjectForm` + clickable `ObjectRefCard` endpoints + `OperationButton`), with centered create dialog. | [relations-catalog-detail/](relations-catalog-detail/README.md) |
| **Catalog ↔ multi-tab detail** (`platform:Application`) | Paged catalog with scope/sort filters navigating to a multi-tab detail workbench (`tab`, sub-lists, modal editors, owner-declared scalar outputs from `ObjectHeader`, nullable `total` counts). | [applications-catalog-detail/](applications-catalog-detail/README.md) |
| **Workbench canvas** (`ObjectGraph`) | Node-and-relation graph exploration with `ObjectCount` header strip, searchable resource sidebar, `ObjectGraph` canvas (visible-graph shortest path, per-user layout), and right-hand detail inspector. | [ontology-graph-workbench/](ontology-graph-workbench/README.md) |
| **Minimal two-entry catalog → detail starter** | Lightweight two-entry starter (`panelAddress` navigation + `<page-header :draft="formDraft">` + two-column cards) easy to adapt to customer ontology classes (`Student`, `Order`). | [two-entry-catalog-detail/](two-entry-catalog-detail/README.md) |
| **Single-panel catalog → detail + create dialog** | Same full-width catalog + detail + create dialog in one panel and one entry (also generated by `panel scaffold`). | [catalog-detail-dialog/](catalog-detail-dialog/README.md) |

## Other common shapes

- **Full-width table + inline row actions + modal edit/create:** Compose from `ObjectList` (`config.columns` +
  `valueMap` + `config.rowActions` + rowless `#cell-<key>` / `#row-detail` slots), `<sdk-dialog>`, and `ObjectForm`
  (see [CODE.md](../panel-authoring/CODE.md#custom-list-columns-row-detail-and-per-row-operations)).
- **Customer `ObjectType` edit & create pages:** Combine generic reads (`query`, `record`, `form`, `createForm`) with an
  object-targeted save `Action` and a top-level targetless create `Action` (`target: { source: "none" }`) (see
  [CODE.md](../panel-authoring/CODE.md#customer-objecttype-forms-and-targetless-actions)).
- **Moving an existing page into the product layer:** Follow
  [Migrating an existing page into the product layer](../migrate-existing-page.md).
