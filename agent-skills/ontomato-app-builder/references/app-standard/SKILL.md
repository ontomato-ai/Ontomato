# 照 Ontomato 标准拆应用

这份技能帮你把一个已有的应用，照 Ontomato 平台的标准拆清楚：哪些是界面部件，哪些是数据的来处，哪些是一块块内容，哪些是入口和权限，哪些业务逻辑根本不该留在界面里。拆完得到一份清单，后面照着清单在平台上组装。

拆解完成后，按 [App Builder 技术指南](../../GUIDE.md) 用当前 SDK 写面板、检查、登记并打开应用。用发行的组件目录和属主声明核对清单里能直接使用的能力。

## 先读

先读[规范的原则、模型与写页面须遵守的条文](references/standard.md)，再开始拆。如果手里已经有现成页面（例如旧系统页面或原型页）要直接搬进产品层，配合阅读[把已经写好的页面搬进产品层](../../migrate-existing-page.md)。

## 步骤

### 1. 列出要改造的页面和入口

每张页面记四样：地址、菜单里叫什么、谁能进、页面上能做哪些事。先不拆，只列全。

### 2. 逐张页面拆

照 [references/decomposition.md](references/decomposition.md) 的模板，一张页面出一份清单。核心是把页面上的每一块归到下面五处之一：

| 页面上的东西 | 归到哪 |
| --- | --- |
| 怎么画、怎么交互（列表、表单、图、按钮、树） | 基础组件 |
| 基础组件用本体里的东西实例化（接哪类数据、哪个操作，或对话框指向哪个智能体） | 投影 |
| 这一块内容怎么排、选中了什么、各部分怎么联动 | 面板 |
| 地址、菜单名、谁能进 | 应用的入口 |
| 怎么算、怎么改、谁能做 | 能力层（指标、函数、动作），不留在界面里 |

判断时守这几条：

- **看有没有接上本体里的数据，不看它以后会不会被复用。** 接上了就是投影，哪怕只有一处用。
- **拆完整。** 智能体能读懂、能操作的范围，就是拆成投影的范围。留在页面私有代码里的那一块，智能体看不见也操作不了。
- **界面里不留业务规则。** 页面代码里的计算、校验、状态流转、权限判断，逐条列出来，归到能力层；需要展示“共 12 人，其中 3 人待审”这类带口径的统计时，由能力层指标或内置读法给出数字，基础组件（`RecordTemplate`）把已提供的值填进固定句式，组件本身不计算新值、不推业务结论。
- **一块已经拼好、别处也要用的内容，整块做成一张面板**，放进别的面板里用，不要拆散了重拼。
- **不为将来补全。** 只拆这张页面现在真在用的。

### 3. 把清单里的东西和平台已有的对上

- 本体里已经有的类、关系、指标、动作：记下名字，投影直接引用。
- 本体里还没有的：列成“要先在本体里建的”，这是改造的前置。
- 官方 SDK 已有的组件（对象列表、对象摘要、对象表单、操作按钮、引用选择、关系、树、图表、图谱、上传、Markdown、代码、表格预览等，以随 SDK 发行的组件目录为准）：直接用。
- 官方组件和配置覆盖不了的界面部件（小到列表里的一列、表单里的一个字段，大到一整块）：先核属主读法和官方组件数据口对不对得上（对不上是属主或通用记录一侧该补，不在面板里手画），对得上再查配置，确实接不住才列成要写的组件（写清它画什么、需要哪几样数据、有哪些配置项、交出什么、能发起什么操作）；自写组件是最后手段。
- 投影只绑读的函数和写的函数：平台带几个通用的读函数，哪个类是参数（列出某一类的对象、按标识取某一类的一个对象、标准编辑与新建表单；名册、详情和表单直接绑这些通用读函数并填入类名）；带口径、带计算的读用指标（图表用 `MetricChart`，KPI 卡片用 `MetricCard`，固定句式用 `RecordTemplate`）；写用动作（含目标动作和用于新建/全局操作的无目标动作）；平台对象走内置读法与管理操作。
- 排布和联动归面板：用普通 HTML、CSS（`@container`）和 Vue 在面板里写排布、显隐、跳转与状态联动（常见双栏交互可直接用 SDK 里的 `<two-pane-layout>`，普通排布用 CSS；不在面板模板里读记录字段或写业务计算；页头用纯展示 `<page-header>` + `usePanelFormDraft`；应用可用默认菜单，需要入口共享状态时用[应用外框模板](../templates/app-frame/README.md)）。相同类型的页面可直接参照参考资料里的模板起手。面板由平台直接运行。

### 4. 定应用

一个应用一张入口表：每个入口的地址、对应哪张面板、给面板传什么值、菜单名和分组、谁能进。“谁能进”只有两种写法：本域成员都能进，或者一个属于本应用自己的权限码。

### 5. 自查

- 列表搜索、筛选、排序、翻页保留选中项。指定的对象或位置不可读时原位说明。列表条目和实时表单值由投影的只读输出发布，跨成员用 `{ output: { member, name, path? } }` 接线。
- 关闭或不可用的表单与操作用 `v-if` 或操作声明的可用条件，暂时切走的同对象页签和列表用 `v-show`。人切走或关闭脏表单先确认，智能体在同一页更换脏表单的目标或卸载该表单时会收到 `blocked_unsaved`。
- 外框共享状态由外框声明进地址，经入口的 `inputs` 传给内容面板的对外状态。受入口接线的字段只取入口的值，未传值时用声明默认值。计数由授权菜单项里的投影读取。


- 每张页面上原来能做的事，在清单里都找得到对应的投影和操作吗？
- 有没有哪条业务规则还留在“面板”或“组件”那一栏？
- 有没有同一样数据在两个地方各存一份？
- 有没有哪个组件自己去调接口取数？（应当由平台按投影的声明取来交给它。）
- 面板的状态里有没有把“当前选中的是哪个对象”写死？
- 入口的权限码是不是本应用自己的？

### 6. 产出

- 每张页面一份拆解清单。
- 一张汇总：要先在本体里建的、要挪到能力层的、官方组件与配置接不住而要自己写的组件，各是什么、依赖什么。
- 应用的入口表。

例子见 [references/example.md](references/example.md)。

## 常见的拆错

| 拆错 | 应该 |
| --- | --- |
| 把一整张页面当成一个“大组件” | 页面是面板；面板里是一个个接了数据的投影 |
| 组件里写死显示“订单” | 组件只管怎么画；显示订单是投影的事 |
| 按钮点了以后在界面里改好几个字段再保存 | 做成能力层的一个动作，按钮只发起它 |
| 为了两处显示略有不同，复制一份组件 | 同一个组件，两个投影，配置项不同 |
| 把“当前学期”这类全应用共用的选择存在某张页面里 | 放在应用外框面板的状态里，由入口传给各张面板 |
| 用别的应用的权限码当自己入口的准入 | 用本应用自己的码，或写“本域成员都能进” |
