# Ontomato 产品层与应用组装标准

## 这套标准的原则

教培团队搭自己的应用，平台开发翻修已有页面，都用同一套 SDK 和应用构建技能。目标是平台上的应用都这样组装。已有系统按这套标准适配，外部自定义格式没有原样兼容的约定。

1. **本体化。** 界面上的内容显示了本体里的什么、能做哪个操作，都要声明清楚。业务规则留在拥有它们的地方，数据和权限由拥有者裁决。
2. **对智能体易用。** 既容易写，也能看懂和操作。用智能体熟悉的 HTML、CSS 和 Vue，尽量少规定平台专有写法，给能照着做的例子，报错说清哪里要改。
3. **通用。** 一套模型要装得下所有页面。遇到新场景，先看已有对象怎么组合。
4. **边界清晰。** 每一类只管一件事，每件事只在一处。看它负责画、接数据、排内容、发布入口还是执行任务，就能判断归属。
5. **简单。** 概念和规矩能不加就不加。每条限制都要说得出它防的是哪件具体的坏事，防住就够。
6. **权限不能被绕过，页面不能比原来慢。** 用最小的办法守住这两条底线。先把标准和架子搭起来，再优化性能，不让性能压过易写、易用。

## 一、五类对象各管什么

以教务应用的教师名册为例。表格是基础组件，让它显示教职工类的数据，就有了一个投影。把名册和选中教师的详情放在一起，是一张面板。教务应用给它地址和菜单入口，读者就有了一张可打开的页面。智能体通过这张面板的技能了解当前选中的是谁、能做什么。日常所说的“页面”指这样的使用关系，不另设对象类。

### 基础组件管怎么画、怎么交互

一个界面部件配一份声明。表格可以通用，流程画布也可以专画流程。格式化、排序、选中和算布局属于呈现。业务上怎么算、怎么改、谁能做，分别归事实、能力和治理的拥有者。

| 组件声明 | 要说明的事 |
| --- | --- |
| 含义 | 用一句话讲清部件画什么、能做什么，供人和智能体阅读 |
| 需要的数据 | 每样数据的名称和接受的本体元素类型。图谱画布分别需要点和边 |
| 配置项 | 固定显示选项的名称、类型、默认值和说明 |
| 输入 | 运行时能传入的值及其类型 |
| 输出和操作 | 会交出什么值，例如选中的对象，以及它能发起哪些已登记的操作 |

基础组件随组件包发行。平台 SDK 提供官方包，第三方可以发自己的包。组件名带包名前缀，每个组件都要有独立可读的声明，平台无需执行包里的代码就能查目录。同一套部署里每个包同一时刻只用一个版本。

### 投影管这个部件接本体里的什么

一个投影是一条有身份的记录，指定基础组件、数据来处和显示配置。数据可来自一类东西、一个东西或一个操作。例如名册读一类教职工，详情读传进来的某位教师，“保存”接拥有者登记的操作。组件不自行调业务接口。

每样要读的数据分别起名，写明读谁、用拥有者公开的哪种读法、参数取固定值还是来自输入。同一个指标的定义和计算结果是两种读法。同一读法用两组参数也要分别命名。类型表列出客户本体的类和平台声明的类型、所属层、读法及操作。结果长什么样、操作叫什么、会影响哪些数据，由拥有者声明。缺结果形状的读法、缺名字的操作，登记时均不予接收，并告诉拥有者缺哪一项。按钮和智能体的操作清单都取操作自己的名字。

投影记录保存名称说明、组件、绑定、配置、输入输出类型、初始共享范围和修订号。记录里没有业务数据。平台按声明向拥有者取数，分别向组件提供读取中、无数据、出错和无权的显示。点可读、某一类边无权，图上的点照常显示。打开或回到前台时重读。操作完成后，平台根据拥有者声明的影响，让正在显示相关数据的投影重读。隐藏的投影不在后台取数，重读保住未保存的编辑。

### 面板管一块内容怎样组成

一张面板有名称、页面代码、声明、初始共享范围和修订号。面板只有一种。它可以放投影，也可以整块引用另一张面板。一个成员是一次有名字的放置，同一张面板放两次，就有两个独立的实例。面板内部的位置、联动和状态归面板。地址、菜单名和入口准入归使用它的应用。

### 应用管从哪里进、交付哪些内容

应用是对外发布的单元。它有名字、图标和说明，有入口表、外框面板、交付清单和主题。入口表列出地址、用哪张面板、传什么值、菜单名、顺序和一层分组、谁能进、默认找哪个智能体。交付清单引用所用的面板、投影、组件包，以及随应用带的智能体和技能。主题给平台设计变量赋值。

应用不包含应用，跨应用复用已有面板。平台外壳提供左栏、账号区、打开应用和在对话旁显示页面的地方，属于平台。应用自己的外框是一张普通面板，通常画菜单和当前入口的内容。平台提供默认外框，应用也可指定自己的。

### 智能体管用哪些能力、以谁的身份做事

智能体和应用同级。它的定义包括系统提示词、选用的技能、模型、数据范围、外部工具和执行权限，可以与人对话，也可以受另一个智能体调用。

一张面板一个页面技能。平台从面板声明、投影的数据来处、组件含义和操作生成技能，作者只需写常见做法。面板引用另一张面板时，技能也引用里面那张的技能。平台从发起人能进的入口出发，沿面板之间的引用逐个判使用授权，得出本轮可用的页面技能。同一张面板放在两个入口，仍只有一个技能。

## 二、怎样写一张面板

**页面用 Vue 写。** 模板和普通 CSS 管排布、尺寸、间距和滚动，Vue 管选中、勾选、表单开合等交互。内容里的小标题、分隔线、只切换本页显示的控件可以直接写，也可以用已有基础组件，无须登记投影。业务数据只按投影声明读取，业务改动只走已登记的操作，页面代码不直调业务接口。需要自己画时，可以用 SDK 的数据组件接投影，再用 Vue 画。一次性的小交互留在面板，缺一种界面部件才补基础组件。

**声明写成员、公开状态和常见做法，随面板保存多语言文字。** 新放一个投影时，作者只需指定五样东西，即所用组件、数据来处、组件配置、操作以及输入输出所接的状态。登记工具用组件目录和拥有者的读法推得类型等属性，生成一条普通投影记录，只用一次也一样。投影详情能查到补出的属性，构建技能说明它们的含义和改哪一项会让它们改变。已有投影直接引用。操作需要一份表单草稿时，在声明里指明接哪一个成员的草稿，成员名由作者取。

**公开状态写清类型、是否按人保存、是否进地址、是否对外。** 搜索词这样的简单值存值本身，选中的对象存类型和标识。还可以声明对象内的位置、对象列表或放置列表。共享定义不写死某人当前选中的对象。实例内的临时交互留在 Vue。成员通过声明的输入输出与公开状态相连。

已由外面接上的对外状态只取传入的值，由外面决定是否带进地址。其余状态先取地址或打开时明确给的值，再取这个人保存过的值，最后取声明的默认值。按人保存与进地址可以同时选。智能体替人做事时不改别人的个人设置。业务输入经对外状态传入，身份、权限、语言和主题由平台提供。

**放进来的面板或投影可以固定，也可以按公开状态选择。** 选择范围可以是列出的几项、按对象的类配置的详情面板，或读者有权使用的任一项。面板之间不能循环引用。每个面板实例有独立状态，只通过对外状态传值、取值。需要选择而没有值时，原位显示“请先选择”。选中的内容无权或不可用时，原位说明原因，其余成员照常使用。

里面那张实际显示时，它的操作和公开状态一并交给智能体，技能能指到具体是哪一次放置。在地址里只带外面接出的状态。页头具名快捷方式若要带到一个状态，技能给出能打开该状态的地址。若要发起操作或打开其他入口，技能就使用已有的操作或地址。恢复地址、选中或重绘都不会引发业务写入。

**平台直接运行面板。** 有权编辑并上线代码的人可以提供代码，查看授权只管使用。没有额外的代码批准步骤。隔离框的能力保留，留待以后有新的权限控制需求时再考虑。

面板按可用宽度排布，在整页、别的面板里和对话旁都能用，无须知道自己显示在哪。组件包决定部件外观，只用平台的设计变量。变量依次取平台默认、部署品牌、应用主题，可在某张面板或某次放置上局部赋值。全局变量和组件公开的变量都只收颜色、尺寸等值，不能带地址。平台把面板的 CSS 选择器限在当前实例，组件内部的颜色、字号等通过变量调。这个范围约束不阻止固定定位画出边界，也不禁止普通 CSS 引用外部地址。

## 三、从入口打开，到完成一次操作

**入口属于使用面板的应用。** 菜单名可省，省了的入口仍能从链接打开。一个入口的准入写“本域成员”，或写本应用拥有的菜单权限码。“本域成员”不占菜单权限码。页面归哪个应用按产品决定。另一应用需要相同内容，就引用同一面板，为自己的入口定准入。例如对象详情整页从对象浏览器进入，在个人工作台里打开同一详情时，跟工作台的入口走。

**平台只解析一次地址。** 平台按地址找到入口并判准入，再解出外框和入口面板声明进地址的状态。应用共用且影响内容的值，如当前学期，由外框声明进地址，入口再传给内容面板。当前入口只取自地址。外框的菜单是读取该应用入口的投影，切换就是打开另一个入口的地址。对话旁不画外框，但解析同一地址，拿到同一个学期。去其他页面或站外用普通链接，站内链接照常判准入。

平台画页面标题和返回。标题先取入口的菜单名，没写就取面板名，整页和对话旁取法一致。只有不进菜单的入口显示返回，回到读者来的页面。没有上一页就回本应用首个有权进入的入口。功能页面下方有输入框，对话在智能体平台进行，相关页面按地址开在对话旁。

**三层权限各回答一个问题。**

| 要回答的问题 | 谁判 |
| --- | --- |
| 能进这个入口吗 | 应用按入口的准入和发起人身份判。面板放到别处时，不继承原入口的菜单权限 |
| 能用这块内容吗 | 平台按使用授权判面板和所需投影，放进来的面板也要判。可用与可编辑分别授权 |
| 能读哪些数据、能做哪个操作 | 数据或操作的拥有者在每次请求时按身份判。换入口、藏按钮、拿到面板定义都不会扩大权限 |

人点击，用本人的权限。智能体看得到页面和选中项，可以带人打开某个状态，也可以把草稿填进同一份表单，默认由人保存。智能体要执行时，调用按钮背后的同一个已登记操作，用本轮执行人的权限，默认先向发起人确认，一次意图只执行一次。会话可以设为全自动，执行仍须明确调用。打开、刷新或收到草稿本身都不会执行操作。

## 四、共享、修改和交付

**先看来源。** 面板和投影与应用一样，有域里登记的，也有平台自带的，两者使用同一种作者写法。

| 来源 | 谁能用、怎么改、能引用什么 |
| --- | --- |
| 域里登记 | 按域内授权使用和修改。可以引用获准使用的域内资源，也可以复用平台自带的面板和投影 |
| 平台自带 | 随产品发行，全平台一条记录，各域成员都能用，运行时不能改。用保留编号，域内登记不能占用。投影只绑定随平台发行的类型、读法、操作或预设智能体。要显示某个域里的具体对象，运行时从状态传入。面板源文件里写定的投影只能是自带投影，写入的站内链接只能指向内置入口 |

内置应用的面板入口只指向平台自带的面板。翻修原页时，沿用已定的应用归属、正式地址和权限；逐张替换的做法见内置应用的面板随产品带出设计。要在一个域里改用自己的版本，可以拿源文件另起编号登记，并在自己的应用里使用。

**复用是引用同一份当前定义。** 域内共享面板时，平台按分享者可授的范围，一并办理所用投影的使用授权。投影可以直接由别的面板引用，无须先转成另一种对象。删面板时一并清理只有它使用的投影，别处仍在用的投影保留。

投影、面板、应用保存后就是当前定义，所有引用处都读这一份，修订号用于防并发覆盖。正在编辑的实例保住未保存内容。当前定义没有历史版本可选或回退，组件包自己的发行版本可查。被引用的对象不能普通删除。清理账号是已定的例外，其源卡和图投影可随账号删除，余下的引用明确显示图不存在。

组件包升级时，仍在使用的组件及其数据名、配置项、输入、输出、操作都不能删除或改类型。平台拦下这类变更，并列出受影响的投影和面板。面板的对外状态、投影的输入输出也按真实引用保护，先改使用方才能移除或改类型。平台能核对声明的结构。含义或默认值改变后仍能正常使用，由发布方负责。面板无须各自锁定组件包版本。

**交付的源文件丢失，仍可从平台恢复当前定义。** 在同一部署，只要本体元素、权限、业务服务和组件包发行物还在，有权的人就能打开、使用、继续编辑。面板可恢复的是模板及样式、脚本、声明和常见做法。额外图片、字体等资源需要另行备齐。第三方编译产物不能还原为源工程。迁往另一部署，带工作区源和显式登记材料，在目标环境备齐依赖、配置授权并登记。平台没有一键恢复或整套导出再导入的交付方式。

## 五、用应用构建技能交付

教培团队和平台开发都用应用构建技能（`ontomato-app-builder`）拆页面、查目录、写面板、检查和登记。技能随 SDK 提供，只教相应版本能用的写法，检查命令与平台用同一套解析器。先找已有组件、投影或面板。缺读法、表单或操作，找拥有者补声明和能力。确实缺界面部件，平台开发可补进官方 SDK。翻修已有页面还要按原页面逐项对照人的操作。页面翻成面板

用一张真实页面判断架子和技能够不够用。在开发环境里，新会话只拿技能和待翻的页面，不问底座开发，也能独立翻完。人原来能做的事仍能做，智能体看得到上下文、能起草、能执行。记下用了多久、写了多少、哪里不得不读平台源码、丢了什么行为，用这些证据改技能、组件或平台。做出一张域内试做页能检验写法。正式替换还要在所属应用的原入口证明读者能用、无权者被拥有者拒绝。

## 六、和现在的实现差在哪

以下是 2026-11-21 的交付依据。教培团队使用开发环境，选用能力时要对照该环境配套的技能。源码、试做页和正式入口各能证明什么，见下表。

| 能力 | 当日能确认到哪一步 |
| --- | --- |
| Vue 面板、投影登记、页面技能 | 开发环境的业务知识试做页已用五样短写法一次登记成功。人能操作，智能体能看页面、起草后由人保存、经确认执行。其他页仍会遇到所属类型缺读法、操作或专用智能体拿不到技能。节点实测 |
| 直接运行、按声明读数、样式范围 | 公共开发分支在正式入口和候选预览都直接挂载 Vue 面板，宿主限定样式选择器，按投影声明送到统一读入口。已有旧页面逐张替换，不能据此认定它们都已改接。 |
| 面板里按状态放面板或投影、按人保存状态 | 公共开发分支已有按状态选择的声明、嵌入读取与挂载，以及个人状态读写接口。开发环境里动态切换后智能体能使用里面的操作、重新登录恢复个人状态，待按目标入口核实。 |
| 内置应用原址使用自带面板 | 公共开发分支已有随包收集、登记自带资源和正式入口声明，例如本体管理器的面板目录。哪些页面在开发环境已替换原页，并用无原权限的账号核过数据与操作，以逐页验收为准。 |
| 入口传入共用状态、自定义外框、第三方组件包安装、应用主题 | 上述翻页实测没有给出这几项的完整使用证据，在目标环境是否可用待核。 |
