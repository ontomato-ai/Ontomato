# Ontomato 产品层与应用组装标准

本规范规定产品层的五类对象各是什么、怎样组成应用，写页面必须遵守什么，以及平台保证什么。

## 适用范围

1. 本规范适用于平台上所有应用的组装。外部业务团队搭建自己的应用、平台开发翻修已有页面，使用同一套 SDK 和同一个应用构建技能（`ontomato-app-builder`）；拆页面、查目录、写面板、检查和登记都用这个技能。
2. 已有系统按本规范适配。外部自定义格式不保证原样兼容。
3. 本规范只规定四件事：原则、模型、写页面必须遵守的条文、平台的保证。
4. 术语以《产品共同语言》为准；事实、能力、治理、产品四层的归属以《本体分层》为准；对话与页面的入口及显示形态以《智能体应用范式》为准，智能体怎样操作对话旁的页面按本规范 2.4.2；服务与 SDK 的边界以《总体架构》为准。
5. 无域也要能用的平台运维页面不适用本规范，保持原生页：超管控制台的域管理和账号管理、企业授权、系统监控。产品层的入口准入、使用授权和运行时都按域判定（2.3.1、2.4），无域的 superAdmin 不走这条链路。企业授权和系统监控在系统设置里照旧以原生页出现。

## 一、原则

1. **本体化。** 界面上的内容显示了本体里的什么、能做哪个操作，都要声明清楚。业务规则留在拥有它们的地方，数据和权限由拥有者裁决。
2. **对智能体易用。** 既容易写，也能看懂和操作。用智能体熟悉的 HTML、CSS 和 Vue，尽量少规定平台专有写法，给能照着做的例子，报错说清哪里要改。
3. **通用。** 一套模型要装得下所有页面。遇到新场景，先看已有对象怎么组合。通用也管以后：设计时要问它装不装得下以后的页面，不只是眼前这几张；接不住的时候改通用的那一侧，不给个别页面另开一条路。对外的写法是长期的承诺，作者写下的每个名字、每种写法都会跟很多年，所以对外只露平台自己的名字和入口。
4. **边界清晰。** 每一类只管一件事，每件事只在一处。看它负责画、接数据、排内容、发布入口还是执行任务，就能判断归属。
5. **简单。** 概念和规矩能不加就不加。每条限制都要说得出它防的是哪件具体的坏事，防住就够。规矩越多越容易错，也越不通用：一条规矩只要有一种正当的页面守不了，它就不该是通用的规矩；只对一批页面成立的做法，写成那批页面的做法，不写成规矩。已经定下来的方案尽量维持：要改，得说得出它违反了哪条原则，或者挡住了哪件真实的事；实现上不顺手不算理由，先在已定的范围里找做法。
6. **权限不能被绕过，页面不能比原来慢。** 用最小的办法守住这两条底线。先把标准和架子搭起来，再优化性能，不让性能压过易写、易用。

## 二、模型

### 2.1 五类对象

产品层有且只有五类对象。每类对象的职责和边界如下。

| 对象 | 职责 | 边界 |
| --- | --- | --- |
| 基础组件 | 定义一个界面部件怎样呈现、怎样交互，并附带一份声明 | 只负责呈现：格式化、排序、选中、布局计算。业务数据归事实层，业务计算、判断和修改归能力层，谁有权操作归治理层，都由各自的拥有者负责 |
| 投影 | 把一个基础组件用本体里的元素实例化，成为一条有身份的记录。记录指定基础组件、数据来源和显示配置 | 只能绑定读函数、写函数或智能体，不得直接绑定事实层的类 |
| 面板 | 定义一块内容由哪些投影和面板组成，以及它们的位置、联动和状态 | 地址、菜单名、入口准入不属于面板，属于使用它的应用 |
| 应用 | 对外发布的单元。有名称、图标和说明，定义入口表、外框面板、交付清单、主题、是否允许单独打开 | 应用不得包含应用 |
| 智能体 | 定义使用哪些能力、以谁的身份执行：系统提示词、技能、模型、数据范围、外部工具、执行权限 | 与应用同级。可以与人对话，也可以被另一个智能体调用 |

例：教务应用的学员名册。表格是基础组件；让表格读平台的通用读函数“列出”、类填“学员”，得到一个投影；把名册和选中学员的详情放在一起，是一张面板；教务应用给这张面板一个地址和菜单入口，读者就能打开；智能体通过这张面板的页面技能知道当前选中的是谁、能做什么。

**2.1.1 “页面”不是一类对象。** 日常所说的页面，指应用通过入口使用某张面板的关系。

**2.1.2 基础组件可以通用，也可以专用，有三种来源。** 基础组件可以是通用的（例如表格），也可以专门画一种内容（例如流程画布）。来源有三种：①平台 SDK 提供的官方通用包，它必须覆盖平台自身的全部页面，缺少时先补它；②第三方发行的组件包；③作者单独登记的组件，登记方式与登记面板相同，授权、引用保护和恢复适用面板的规则。

**2.1.3 投影绑定什么。** 投影只能绑定读函数、写函数或智能体。

- 业务本体上，读函数是平台提供的通用读函数或指标，写函数是动作。
- 通用读函数由平台提供，以类为参数（例如列出某一类的对象、按标识取某一类的一个对象），投影从平台的目录里选用；不够用时由平台补充。带口径、带计算的读取必须用指标。
- 平台自己的对象上，读函数和写函数是平台内置的读法和管理操作。它们随平台发行，业务本体不能修改。
- 对话框组件指向一个智能体，也是投影。

例：学员名册读通用读函数“列出”、类填“学员”；详情读“取一个”；“在读人数”读一个指标；“保存”绑定一个动作；本体管理器的关系类型目录读平台内置的“列出关系类型”。

**2.1.4 面板只有一种。** 面板里可以放置投影，也可以整块引用另一张面板。一次有名字的放置称为一个成员；同一张面板放置两次，得到两个互相独立的实例。直接放在面板里的不绑定数据的官方界面件（页头、按钮、弹层等）不算成员。放置的内容可以固定，也可以按公开状态选择（例如工作台上用户自己摆的卡片）。面板之间不得循环引用。

**2.1.5 跨应用复用，引用已有的面板或投影。** 另一个应用需要相同的整块内容时，引用同一张面板，并为自己的入口单独规定准入；只需要其中一个投影时，由自己的面板直接引用该投影。

**2.1.6 一张面板对应一个页面技能。** 页面技能由平台根据面板声明、投影的数据来源、基础组件的含义和操作生成；作者只编写其中的常见做法。同一张面板被多个入口使用时，仍然只有一个页面技能。

### 2.2 层级

界面的层级只有一套，从外到内四层：

1. **平台外壳**：左栏、账号区、打开应用的入口、在对话旁显示页面的位置。属于平台。
2. **应用的外框面板**：左栏以内的整块区域属于应用，由应用的外框面板绘制。应用自己的菜单、分组、菜单上的数字以及其他共用内容，都由外框面板绘制。
3. **当前入口的面板**：外框面板留出一个位置，放置当前入口对应的面板。
4. **面板内部**：放置其他面板、投影和不绑定数据的界面件。

每个应用都必须有外框面板；不自行编写的，使用平台提供的通用外框面板。外框面板是一张普通面板。平台不替应用绘制菜单。

自行编写外框面板时：菜单用读取本应用入口的投影绘制，切换菜单就是打开另一个入口的地址；外框面板留出一个位置放置当前入口的面板；应用内各入口共用、并且影响内容的值（例如当前学期），由外框面板声明并写入地址，再由入口传给内容面板。

### 2.3 入口和打开方式

**2.3.1 入口属于使用面板的应用。** 一张页面归哪个应用，按产品决定。面板被另一个应用使用时，准入由那个应用的入口规定。例：对象详情整页从对象浏览器进入；在个人工作台里打开同一张详情面板时，准入按工作台的入口判定。入口的准入由使用面板的应用声明：对本域成员开放，或者要求本应用自己的菜单权限；没有列入菜单的入口仍然可以按地址打开。

**2.3.2 同一个入口地址有三种打开方式：** 在平台内打开；在对话旁打开；通过对外链接单独打开。各种获准的打开方式下，入口面板、联动和权限相同；面板不需要知道自己处于哪一种。对话旁不绘制应用的外框；应用允许单独打开时才有对外链接。

### 2.4 权限

权限分三层，每层只回答一个问题，互不替代。

| 问题 | 由谁判定 | 规则 |
| --- | --- | --- |
| 能否进入这个入口 | 平台的应用目录 | 应用声明每个入口的准入条件，应用目录按发起人的身份判定。面板被别处使用时，按使用它的那个入口判定，不继承原入口的菜单权限 |
| 能否使用这块内容 | 平台 | 按使用授权判定面板和它所需的投影，嵌入的面板同样判定。使用授权和编辑授权分开授予 |
| 能读哪些数据、能做哪个操作 | 数据或操作的拥有者 | 每次请求时按身份判定。更换入口、隐藏按钮、取得面板定义，都不会扩大权限 |

**2.4.1 人的操作使用本人的权限。**

**2.4.2 智能体的操作。**

**人和智能体操作页面的逻辑一致：同一份表单、同一个按钮、同一个接口、同一份权限。** 这里规定智能体怎样操作对话旁的页面：智能体按页面的声明发出请求，填表和执行由当前这张页面走人操作时原有的入口办理。页面上人能修改的内容和能执行的操作，必须同样提供给智能体；页面上没有的，智能体也没有。用户在使用智能体时，智能体继承这个用户的权限：用户能改、能做的，智能体才能改、能做；智能体配置里的默认身份只用于没有用户在场的自动化场景。没有页面的后台任务和被派出去执行任务的智能体不操作页面，按能力层的规则办事。只在回复里给出链接，不算完成。

智能体可以看见当前页面、跳转、修改公开状态、填写表单，并请求页面执行这个用户能执行的已登记操作（包括保存）：

- **看见。** 智能体能读取对话旁面板的公开状态的当前值（例如页签、筛选、选中项、视图模式）和表单里当前填写的内容（包括用户尚未保存的修改）。用户发送消息时，智能体得到当时的公开状态和表单内容；这一轮当中可以按需再读，读到的是读取时最新的内容，包括用户中途的修改；智能体每次请求改动页面之后，得到实际改动的结果。页面上显示的其他业务数据，智能体按页面声明的读法，以这个用户的身份、在本轮数据范围内向拥有者读取。
- **跳转。** 智能体可以把对话旁的页面换到另一个入口或另一个对象，也可以主动打开一张页面来辅助说明，在发起的当轮显示结果。跳转是一次导航：目标入口，以及恢复这个导航目标所需的状态（例如目标对象、指定的页签），写入地址，刷新后恢复；哪些状态随导航恢复，由面板声明为写入地址。用户只开着对话时，页面开在对话旁；已经并排的保持并排，已经占满的保持占满。跳转到发起人没有准入的入口时不打开，智能体得到拒绝的原因。
- **改状态。** 智能体可以修改面板已声明的公开状态，包括没有声明写入地址的那些。修改在发起的当轮显示结果，不重新加载页面，不引发业务写入。
- **填表。** 智能体请求填表时，页面用这份表单原有的编辑入口填入字段，在发起的当轮显示结果；改动的字段必须标出，表单保持未保存。表单里已有用户尚未保存的修改时，页面保留这些修改，由智能体在对话里先问用户。智能体填进去的内容和人填的一样对待：没保存就是未保存，离开页面时同样提示有未保存的修改；不另设“草稿”这种对象。
- **保存和执行。** 页面技能向智能体提供页面上已登记的操作，保存也在其中。智能体请求执行时，由当前页面经按钮原有的入口准备这次操作；默认在当轮对话里向发起的用户说明以谁的身份、对哪个对象、做什么以及它的影响，本人确认后页面才提交。用户同意的是当时那一件事：对哪个对象、做什么操作、提交什么内容。这件事变了，或者已经做过了（包括用户已经自己手动保存），就不能再凭这次同意去做。等待保存确认时，表单保持未保存。同意失效以后，用户仍然可以自己在页面上操作；智能体要继续，须按当前页面重新请求确认。每笔意图只执行一次。会话可以设置为全自动，全自动时省去对话里的确认，仍然由页面执行同一次明确的请求。
- **只能由人做的两类。** 要用户从自己设备上选文件的操作（上传、导入）由人来做，智能体可以把页面带到那个入口，不替人选文件、不代为提交。属主标为秘密的字段（密码、密钥），值不交给智能体，智能体也不代填；操作生成的秘密只交给操作的人。这两类是上面“人能做的智能体同样能做”“智能体能读取表单里当前填写的内容”的例外。
- 修改用户显示的只能是正在和用户对话的那个智能体；被派出去执行任务的智能体不得直接修改。
- 读取业务数据必须遵守本轮数据范围（定义见《产品共同语言》“智能体配置”），并由数据的拥有者按请求的身份判定权限；用户在场和无人自动化时各用谁的身份，见《智能体应用范式》。

### 2.5 来源和当前定义

**2.5.1 面板、投影、应用各有两种来源，写法相同。**

- 域内登记：按域内授权使用和修改。
- 平台自带：随产品发行，全平台只有一条记录，所有域都可以引用它的定义，运行时不能修改。能否进入入口、能否使用内容、能读写哪些数据，仍按 2.4 逐层判定。编写平台自带的面板时，写定的投影、站内链接和入口目标按《产品层面板》“平台自带的面板和投影”和《应用与入口》“内置应用”办理；翻修原有页面沿用原来的应用归属、正式地址和权限。

**2.5.2 保存即当前定义。** 投影、面板、应用保存后就是当前定义；复用是引用同一份当前定义，所有引用处读取同一份。不提供历史版本的选择和回退。

### 2.6 代码的运行和信任

平台直接运行面板的代码和作者登记的组件的代码，不设代码审批。有编辑授权的人可以提供代码，使用授权只允许使用。作者必须按 3.1 使用声明的数据和操作，并遵守确认的要求；这些守不守靠的是作者，平台不在运行时强制。这是认下的取舍，前提是写代码的人是受信任的。每一次业务请求的权限仍由数据或操作的拥有者按请求人的身份判定。隔离运行的能力保留，出现不受信任的作者（例如对外开放）时再启用。

## 三、写页面必须遵守的

### 3.1 由作者遵守的

**写面板：**

1. 面板用 Vue 编写，以模板和标准 CSS 排布，用 Vue 表达页面交互；文件怎样组织见应用构建技能。面板必须按所在容器的宽度和高度布局，容器变化时布局随之调整。同一份代码放在整页、嵌入其他面板、对话旁三种位置，都必须能正常工作；不要求各个宽度下长得一样，面板也不需要知道自己显示在哪一种位置。容器没有确定高度时，面板按内容撑高；高度怎样用由面板自己定。
2. 面板读取业务数据必须通过投影，修改业务数据必须调用已登记的操作，不得直接请求业务接口。发起业务修改的按钮，必须调用本面板某个投影成员已经绑定的具名操作；只处理页面交互的按钮（例如打开弹层、返回、跳转、放弃未保存的草稿），可以直接写在面板里，也可以使用组件提供的按钮。
   - 按钮画在页头、表格的插槽还是表单里，调用的都是同一份绑定；操作作用于谁、参数从哪里来，从这份绑定和成员的接线查得到。
   - 保存绑定在表单自己的投影上时，提交的就是这份表单正在填写的内容；别的成员上的操作要用到某份表单正在填写的内容时，必须在声明里指明取哪一个表单成员的。
   - 操作完成后要更新界面状态或导航的，必须以这个操作的成功结果为依据；后面要用到对象标识的（例如新建后跳到新对象），由操作的拥有者声明并返回。面板不得根据列表的变化推断操作成功，也不得推断新对象的标识。
3. 面板不得自行渲染本体数据。业务数据由基础组件按投影的声明呈现；从投影的读绑定和显示配置，必须查得到显示的是哪个结果、哪个字段或哪个对象。
   - 例外一：尚未保存的编辑内容（表单、画布、向导里的草稿）不属于本体数据，面板可以通过该组件声明的草稿输出读取，用于实时预览。
   - 例外二：投影已声明的输出可以填入标题、页签等只接收文字的位置（见第 5 条）。
   - 不显示本体数据的静态内容和只切换本页显示的控件，直接写在面板里或使用已有的基础组件，不需要登记投影。
4. 面板和基础组件不得实现业务计算和业务判断。读取中的业务计算和判断由指标提供，写入中的由动作提供；平台自己的对象使用平台内置的读法和管理操作。基础组件可以改变已有值的显示形式，例如按格式显示日期和数字、套用固定的句式、按配置对应成文字、颜色或图标。对已经完整读到的列表，基础组件可以做纯文字匹配，并把当前匹配的条数作为这张列表的显示输出。基础组件不得据此产生新的业务值，不得判断业务结论（例如把“超过 3 人”判成“异常”）。筛选要跨分页、决定业务范围或带业务口径时，必须使用拥有者声明的读法；需要显示总数时，使用该读法返回的总数。
5. 面板可以使用的业务值仅限投影已声明的输出（例如选中的对象及其名称、记录条数、当前值）。这些输出是只读的，不需要建成公开状态，可以用于三处：作为其他成员的输入；决定显示哪一块、选中哪一项、跳转到哪里；填入标题、页签等只接收文字的位置（可以带固定的前后缀）。面板不得读取记录的字段，不得自行做业务计算；用这些值判断有没有、是不是、是否为零来决定显示哪一块，不算业务计算。
6. 面板在加载、恢复地址、选中、重绘时不得发起业务写入。业务写入只在用户明确操作、或智能体明确调用已登记的操作时发生。
7. 使用官方组件按以下顺序，前一步满足不了才用下一步：①默认外观；②组件的配置项；③在组件提供的插槽里放置其他组件；④自行编写一个组件来渲染整块内容，这是最后的手段。插槽里的组件只呈现官方组件传给它的值时，直接放置，沿用官方组件所在的投影；需要另外读取本体数据时，在面板声明里登记相应的投影成员，并从插槽接入所需的行或对象。按行的业务操作声明在提供这一行的表格投影上，插槽里的按钮调用这份声明。
8. 页头不由平台绘制。面板需要页头时，把官方页头组件放在内容顶部，按需提供标题、说明、返回和操作按钮；不放置就没有页头。页头上的按钮遵守第 2 条。
9. 面板声明列出所用的成员和公开状态。需要由智能体读取和修改的页面交互状态，声明为公开状态；其中下面两类必须声明：决定读者看到哪一部分业务内容的状态（页签、筛选、选中项、视图模式）；打开或切换可供人填写的业务表单的状态（包括只打开空白新建表单的弹窗）。不改变业务内容的临时交互（悬停、帮助提示的展开、滚动位置）留在 Vue 里，不声明。
   - 每一次放置的投影或嵌入的面板都是成员，在放置处声明它的输入输出怎样接线；直接使用作者登记的组件时，在声明里单独列出；不绑定数据的官方界面件不列。
   - 每个公开状态写明类型，按需开启按人保存、写入地址、对外开放（允许外层面板接线的称为对外状态）。嵌入的面板，状态要写入地址时，由外层面板接出并声明。
   - 写入地址的只是“别人拿到这个链接，要回到同一处”所需要的状态：看的是哪个对象、停在哪个页签或视图；列表的搜索词、筛选和排序可以写入地址。弹窗的开关、正在编辑哪一条不写入地址。
   - 有需要告诉智能体的典型操作步骤时，作者补写为这张面板的常见做法。
10. 实现页面前先查找可复用的基础组件、投影和面板。缺少业务能力（读函数、表单、操作）时，由该能力的拥有者补充声明和能力；确实缺少界面部件时，平台开发可以把它补入官方 SDK。翻修已有页面时，必须对照原页面逐项核对用户能做的操作。

11. 基础组件不得直接请求业务接口，数据由平台按投影的声明提供。声明里的“含义”必须写到人和智能体读了就知道这个组件画什么、能做什么。

**正反例。** 下表举例说明 3.1 各条；符合所引条文的其他写法同样可以。

| 场景 | 错的写法 | 对的写法 | 依据 |
| --- | --- | --- | --- |
| 显示学员的姓名和班级 | 面板的模板里直接读记录的字段来显示 | 放一个绑定“取一个学员”的详情投影，由基础组件显示 | 第 3、5 条 |
| 页头标题要带上当前学员的名字 | 面板去读记录，自己拼标题 | 用投影声明的输出“选中对象的名称”，填进页头标题：“详情 - 张三” | 第 5 条 |

| 页头上的“新建”，只是打开一个弹窗 | 登记成投影 | 普通按钮，直接写；它打开业务表单的那个状态要声明成公开状态，不写入地址 | 第 2、9 条 |
| 表格每一行的“删除” | 插槽里的按钮自己去调接口 | 删除操作声明在表格投影上，插槽里的按钮调用这份声明 | 第 2、7 条 |
| 表格的一格想显示成带图标的名称 | 自己写一个组件，把整张表重画一遍 | 先用表格已有的外观或配置；不够时，在单元格插槽里放一个只显示传入值的组件 | 第 7 条 |

### 3.2 写错会被查出来的

下面几条写错时，平台的检查和登记会查出来，指出错在源文件或声明的哪里、该怎样修改，所以不需要作者记。检查只查得出认得出来的结构和写法错误，查不出来的仍归作者负责；3.1 的各条不因为通过了检查就算守住了。由哪个入口检查、识别哪些写法见《产品层面板》和《组件与组件包》。

1. 不绑定数据的界面件（按钮、页签、弹层、不接数据的普通表格等）从平台 SDK 引入，使用 SDK 的组件名，不得直接引用第三方界面库的组件名。
2. 面板声明必须符合平台规定的结构。公开状态必须声明类型；按人保存、写入地址、对外开放分别按需开启，未开启时为否。投影的作者填写基础组件、绑定和用到的显示配置，可以确定的其余属性由平台推导；已登记的投影直接引用。
3. 基础组件声明含义，以及它实际使用的数据、配置和交互（输入、输出、操作）；没有用到的可以省略。声明的结构见《组件与组件包》。
4. 检查发现面板或作者登记的组件的脚本直接请求业务接口时，报错，并提示改用投影读取或调用已登记的操作。接口的权限仍由拥有者在每次请求时判定。

## 四、平台的保证

以下由平台实现并负责，作者不需要处理。每条的细节见括号里的能力页。

1. **取数。** 平台按投影的声明向数据的拥有者取数，使基础组件能区分加载中、无数据、出错、无权限。面板打开、回到前台和操作完成之后的数据更新由平台负责，并保住未保存的编辑内容；面板不需要自己刷新数据。（《产品层面板》）
2. **状态。** 公开状态取值的优先级固定：已被外层接入的对外状态，取外层传入的值；其余状态依次取地址或打开时指定的值、当前用户保存的值、声明的默认值。身份、权限、语言、主题由平台提供。（《产品层面板》）
3. **不误写。** 平台自身在打开、刷新、恢复地址、选中时不触发业务写入。智能体代用户操作时，不修改其他用户的个人设置。（《产品层面板》《智能体》）
4. **嵌套。** 同一张面板放置多次，各实例状态独立。嵌入的面板显示时，它的操作和公开状态同样提供给智能体。面板之间不得循环引用。（《产品层面板》）
5. **样式和主题。** 面板的样式只作用于本实例，不影响其他面板。组件外观由组件包决定；随主题变化的部分使用平台的设计变量，接受主题和局部的覆盖。（《产品层面板》《组件与组件包》《应用与入口》）
6. **地址和区域。** 地址要短、人读得懂：每个写入地址的状态是一个有名字的普通参数，平台不把一包状态序列化后塞进地址。站内链接打开时，平台按目标入口判定准入。平台在挂载内容、重新显示已有的页面实例、向本轮智能体提供页面上下文和技能之前，确认目标入口的准入和实际放置路径上面板、投影的使用授权有效。平台向应用的外框面板提供一块高度确定、随窗口变化、没有内边距的区域；在对话旁直接提供给入口面板。页底输入框由平台提供，不占面板的布局空间；入口可以声明不显示它（例如页面本身就是对话）。（《应用与入口》《对话外壳》《产品层面板》）
7. **引用保护。** 被引用的对象不能普通删除（已定的例外见《产品层面板》《仪表盘》）。组件包升级时，在用的组件和它的接口受保护，不会被移除、删除或改变类型（《组件与组件包》）。共享面板时，平台在分享者可授的范围内，把所用投影的使用授权一并授予。（《组件与组件包》《产品层面板》）
8. **恢复。** 交付的源文件丢失后，用户可以从平台恢复自己有权读取的面板、投影、应用和作者登记的组件的当前定义；写回仍需要相应的编辑授权。（《组件与组件包》《产品层面板》）
