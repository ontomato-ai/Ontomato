# Ontomato 产品层与应用组装标准（第二版，2026-11-20）

本标准规定产品层的五类对象各是什么、怎样一层层组成、怎样发布成应用，以及贯穿各类的规则。这是平台的标准：已有系统按它来改，不承诺外部自定义格式原样兼容。

文中说的“本体”分事实、能力、治理、产品四层：事实是类、对象和关系；能力是指标、函数、动作、流程；治理是权限和规则；产品就是本标准讲的这五类对象。

## 这套标准的原则

给标准加任何规矩之前，先拿这六条对一遍。

**起点**

1. **本体化。** 界面上每一块显示的是本体里的什么、能做本体里的哪个操作，都要声明出来。业务规则不写在界面里，数据和权限由拥有者判。

**目标**

2. **对智能体易用。** 写起来容易，用起来也容易（能看懂页面、能操作）。写这一面：尽量用智能体本来就会的东西（普通的 HTML 和 CSS），平台自己规定的写法越少越好，有例子可抄，报错说人话。

**对模型本身的要求**

3. **通用。** 一套模型装得下所有页面；遇到新情况先拿已有的去套，不为一个场景新造概念。
4. **边界清晰。** 每一类只管一件事，每件事只在一处。判断一样东西归哪一类，能用一句话问出来（见第二部分末尾）。
5. **简单。** 概念和规矩能不加就不加；每加一条限制，要说得出它防的是哪件具体的坏事。

**底线**

6. **权限不能被绕过；不能比原来的页面慢。** 只用最小的办法去守，不能反过来压过第 2 条。性能放在架子搭完以后再优化，不作为现在取舍的理由。

“更简单”“更省工”要用实测说话：让一个不带上下文的新会话只拿技能去做，记下用了多久、写了多少、卡在哪。

## 一、总的结构

两件事分开：**内容怎么组成**，和**内容怎么发布**。

- 内容怎么组成：基础组件 → 投影 → 面板。面板可以放进面板。
- 内容怎么发布：应用。它决定入口、谁能进、交付什么。
- 智能体和应用同级，通过技能使用面板。
- 平台外壳（左栏、账号区、放应用的区域、把页面开在对话旁）是平台提供的框，不属于这五类，也不是应用。

每件事只在一处：怎么画在基础组件，数据从哪来在投影，一块内容怎么排、怎么联动在面板，地址、菜单和谁能进在应用的入口。

**以后给这套标准加规矩时照这三条判断**：

- 标准的路给的是能力：照声明写的面板，平台能直接渲染，智能体能读懂、能起草、能操作。
- 自由的路一直留着：排布和交互用普通的 HTML、CSS 和代码就能写，写完就能用。
- 每条限制要说得出防的是哪件具体的坏事，防住就够，不顺带拦住正常使用；不让“写出来”等“人批”。

## 二、每类对象的定义

### 1. 基础组件

**定义**：一个界面部件，加一份声明。部件只管怎么画、怎么交互，不知道自己将来显示谁的数据。

“不带业务”的意思是：不含怎么算、怎么改、谁能做这些业务规则。它可以专为某一类东西而画（例如流程画布只画流程），这仍然是基础组件。纯呈现的计算（格式化、排序、选中、算布局）是组件自己的事。

**声明有五栏**：

| 栏 | 写什么 |
| --- | --- |
| 含义 | 一句话：它画什么、做什么、不做什么。人和智能体读的都是这一句 |
| 需要的数据 | 它需要哪几样数据，每样一个名字，各接受本体里哪类元素。多数组件一样，图谱两样（点、边） |
| 配置项 | 固定不变的显示选项：名字、类型、默认值、说明 |
| 输入 | 运行时别人传给它的值，每个有类型 |
| 输出和操作 | 它交出去的值（如“选中了哪个”），它能发起的操作（每个对应一个已登记的操作名） |

**从哪来**：组件包。平台的 SDK 是官方的那一个包；第三方可以发自己的包。组件的名字带包的前缀，不会重名。没有声明的组件进不了包。声明是一份单独的数据，平台读声明不需要运行包里的代码。一套部署里每个包同一时刻只有一个版本在用。

**约束**：

- 外观只用平台的设计变量。
- 不自己调接口取数，数据由平台按投影的声明取来交给它。
- 加载中、没有数据、出错、无权，这四种样子由平台统一给。组件需要几样数据，就按每一样分别给：图谱的点读得到、某一类边无权时，点照常显示，只有那一类边显示无权。

### 2. 投影

**定义**：一条记录，写明用哪个基础组件、它需要的每样数据从本体的哪里来、配置项填什么。基础组件接上了本体里的数据，就是投影。

**数据的来处只有三种**：

- 一类东西：例如所有定时任务，或“教职工”这个类的所有对象。
- 一个东西：例如这个指标、这个智能体。可以写死，也可以由输入传进来。
- 一个操作：例如“立即运行”。

**每样数据要写全三件**：来处是谁；用它的哪一种读法；读法要的参数从哪来（配置里写死，或接到投影的输入上）。读法由这类东西的拥有者公开，例如指标有“它的定义”和“算出来的结果”两种读法，是两样不同的数据。组件只接结果，不按名字猜接口，也不自己补口径。同一个东西用不同参数读两次，是投影里的两样数据，各有各的名字。

**接上操作不等于执行**：接上一个操作，只是让组件能发起它。打开、刷新、恢复状态都不会执行；只有人的一次操作或智能体的一次明确调用才执行。

**类型表**：“有哪些类型、每类有哪些读法和操作”来自一张统一的类型表：客户本体里的类，加平台声明的类型，每个类型标明属于事实、能力、治理、产品哪一层。智能体、流程、业务知识、文件都是表里的一行；多一种东西加一行，规则不变。

**数据的新旧由平台协调**：操作的拥有者声明它影响了什么，操作做完，平台让读到受影响数据的投影重读。组件和面板不写刷新。看不见的投影不在后台读；正在编辑、还没保存的内容不被重读覆盖；打开和回到前台时重读，以带上别处的改动。

**记录里有**：身份、名称说明、所用组件、每样数据的来处读法和参数、配置项、输入和输出的类型、初始共享范围、修订号（只防并发覆盖）。投影里不存数据，数据每次由拥有者按查看者的身份现给。

### 3. 面板

**定义**：一块内容，由两部分组成：**页面代码**和一份**声明**。只有“面板”这一个概念，没有别的种类名。

**页面代码**是普通的 Vue：一个模板、一段 CSS、一小段脚本。怎么排、怎么交互都在这里写——选中了哪一行、勾了哪些、什么时候显示新建表单，照常用 Vue 写。接了本体数据的每一块，用 SDK 的组件放一个投影；没接本体数据的界面控件（标题、分隔、只切换本页显示的开关）直接写，它们不是投影。

**声明**只写三样，平台和智能体靠它读懂这张面板：

- **用到的投影**：每个起一个名字，写明用哪个组件、数据从本体哪里来、用哪几个操作。直接写在面板文件里，登记时平台替它建成投影对象；也可以引用已有的投影。
- **公开的状态**：智能体要读写的、地址要恢复的、别的面板要传进来的，比如选中了谁、搜索词。每个定类型（简单值、一个对象、对象的列表等），以及按不按人保存、进不进地址、对不对外。只在页面里用的临时状态不用声明。
- **给智能体看的常见做法**，和多语言文字。

**规则**：

- 业务数据只通过投影读，业务上的改动只通过已登记的操作做；页面代码里不直接调业务接口。恢复地址、恢复选中、重新绘制都不会引发写入。
- 公开状态的值是引用（类型加标识），不存数据的副本。共享的面板定义里不把“当前选中的是哪个业务对象”写死。
- 面板的 CSS 只对这张面板自己生效，由平台保证；改不了投影里面组件的样子，要调组件的颜色字号就给设计变量赋值。面板要在给它的任意宽度下能用。
- 去别的页面或站外用普通的链接，站内地址和地址栏里的写法一样，进去时照常判准入。
- 面板可以放进面板：被放进去的是它自己的实例，状态独立，外面那张通过它公开的状态给它传值、从它取值；不能成环；看的人对里面那张也要有使用授权。

**记录里有**：身份、名称说明、页面代码、声明、常见做法、多语言文字、初始共享范围、修订号。

**面板没有**：地址、菜单名、谁能进。

### 4. 应用

**定义**：对外发布的单元。面板管内容怎么组成，应用管面板没有的几件事。

| 应用有 | 写什么 |
| --- | --- |
| 身份 | 名字、图标、说明：左栏和应用广场里的那一项 |
| 入口表 | 每个入口：一个地址、对应一张面板、给这张面板传什么值、菜单名、先后和一层分组、谁能进、默认找哪个智能体。不写菜单名的入口不进菜单，只能从链接或别的面板打开 |
| 外框面板 | 应用自己的框：通常是菜单加当前入口的面板。平台给一张默认的，应用可以换成自己的 |
| 交付清单 | 这个应用包含的面板和投影、用到的组件包、带的智能体和技能。都是引用，不是副本 |
| 主题 | 对平台设计变量的一组覆盖值，对应用里所有内容生效 |

**一个地址只解析一次，由平台做**：

1. 地址里有三部分：哪个入口；外框面板声明进地址的状态；入口那张面板声明进地址的状态。更里面的面板要进地址，由包着它的那张接出来。
2. 平台按地址找到入口，按这个入口的“谁能进”判过，才往下走。
3. 平台按外框面板的状态声明取出共用上下文的值，按入口的“传什么值”交给内容面板。
4. “当前是哪个入口”只由地址得出，平台把它作为输入交给外框面板；外框自己不另存一份。切换入口就是跳到那个入口的地址。

所以：

- 应用里各张面板共用、又会影响内容的上下文（如“当前学期”），声明在外框面板里，并且进地址。入口把它传给内容面板后，内容面板的那个状态就只来自它，两边不会各显示各的。分享出去的地址带着它，别人打开看到的是同一个学期。
- 把页面开在对话旁时不画外框，但地址的解析是同一套，内容面板拿到的业务上下文和整页打开时一样。
- 准入只在第 2 步判。外框面板是普通面板，但它承载哪个入口不由它自己说了算；改状态、换成员都绕不过入口的准入。
- 一张面板业务上需要的输入，只能来自它标了对外的状态，谁打开谁传。没传就用上面说的先后取值，都没有就显示“请先选择”。是谁在看、有什么权限、用什么主题和语言，由平台给，不走状态。
- 外框面板的菜单是一个投影，数据来处是“这个应用的入口”这一类东西。
- 入口的“谁能进”只有两种写法：本域成员都能进；或者一个属于本应用自己的菜单权限码。不能填别的应用的码。“本域成员都能进”只是一种准入写法，不对应任何菜单权限，所以几个应用都这么写互不相干。
- 应用不包含应用，跨应用的复用靠面板。

### 5. 智能体

**定义**：一份可以反复使用的定义：系统提示词、选用的技能、模型、数据范围、外部工具、执行权限（用谁的权限做事）。可以被人直接对话，也可以被别的智能体调用。

**和面板的关系**：一张面板一个技能，由平台从面板的声明、投影的数据来处、组件的含义和操作自动得出，只有常见做法要人写。面板里放了别的面板，它的技能指向里面那张的技能，不抄一份。智能体能用到哪些面板的技能，取决于发起人能进哪些入口、对这些面板及其依赖有没有使用授权。

## 三、贯穿各类的规则

1. **面板怎么运行**。面板一律由平台直接运行，带不带代码都一样。
   - 能编辑并上线面板代码的人，就是被信任的代码提供者。得到一张面板的查看授权，不等于有权改它的代码。
   - 面板带了代码，业务上能做的事不因此变多：读数据只走按投影声明的读入口，写只走已登记的操作，都由拥有者按身份判。
   - 面板的 CSS 由平台圈在面板自己里面。
   - 把面板放进隔离框里运行的能力留着，但现在不用，也不是一种正式的跑法。以后要运行不受信任的代码、做更细的权限控制时再看。
   - 避免组件泛滥：一次性的小交互直接写在面板里；业务上要算的放到能力层；只有真正新的界面部件才做成组件。
2. **只有当前定义，引用不复制**。投影、面板、应用都只有一份当前定义，改了，所有引用它的地方跟着变。修订号只防并发覆盖。“改了就生效”指的是保存后它就是当前定义；正开着、还有没保存内容的实例不被强行换掉，沿用已定的草稿保护。
3. **被用着的不能删，也不能改坏**。
   - 投影、面板、应用被引用时不能删。
   - 组件包升级时，平台拿新旧声明对照：正被用着的组件、数据名、配置项、输入、输出、操作，不能删、不能改类型，否则拦下来并列出受影响的投影和面板。所以面板不用各自锁组件包的版本。
   - 同样的规矩适用于面板标了对外的状态、投影的输入和输出：被别的面板接着时不能删、不能改类型，由它的拥有者负责，改之前处理掉真实的使用方。
   - 对照声明保证的是结构对得上，保证不了行为不变（同一个名字换了含义、默认值变了）。行为上的兼容由发布方负责，平台不替它担保。
4. **权限三层，各判各的**。能不能进：入口上的菜单权限，谁能进跟着用它的那个应用走。能不能用这张面板、这个投影：使用授权。能看到什么数据、能做什么操作：数据和能力的拥有者按身份现判。界面上藏起来不算权限。
5. **人和智能体用同一套**。智能体调的是按钮背后的同一个操作；默认起草，由人保存；执行先向发起人确认，只做一次；会话可以设成全自动。人用自己的权限，智能体用这一轮执行人的权限。
6. **业务不进产品层**。怎么算、怎么改、谁能做，在事实、能力、治理三层；产品层只引用。
7. **样式各归各处**。
   - 长什么样（颜色、字号、圆角、阴影、深浅色）归组件，写在组件包里，只用平台的设计变量。
   - 设计变量的值一层盖一层：平台默认、部署的品牌、应用的主题，再往下可以只在某张面板、某个成员上盖。变量分两种：全局的（主色、字号、圆角），和每个组件自己交出来的（如表格的行高、按钮的底色）。改的都是变量的值，不是组件的样式代码；值只能是颜色、尺寸这类，不能带地址。
   - 摆在哪、占多宽、间距多大、哪一块滚动，归面板的排布，用普通的 HTML 和 CSS 写。
   - 面板里的标题、说明文字、分隔、徽标这类，用对应的基础组件，样子由配置项选。
   - 面板的 CSS 只对这张面板自己生效，由平台保证。
8. **丢了交付的源也能恢复**。应用运行需要的定义都在平台的记录里，交付的源丢了，只要它依赖的本体元素、权限、业务服务和组件包的发行物还在，就照样能打开、能用、能继续改。“能继续改”指平台里存着的定义，不是把第三方编译好的组件包还原成源工程。搬到另一套部署，用源和登记材料在目标环境登记。
9. **对话只在智能体平台**，其他应用的页面按地址开在对话旁；功能页面下方有输入框。

## 四、怎么判断这套标准够不够用

用实测：让一个不带上下文的新会话只拿技能去翻一张真实的页面，记下用了多久、读没读平台的源码、写了多少、卡在哪、有没有丢掉原来的行为。人原来能做的都能做、智能体能看到能起草能执行，而且不费劲，才算够用。费劲就去改技能、组件和平台，不让写页面的人去适应。

## 五、定了不做、对外会被问到的

- 投影、面板、应用的当前定义不提供历史版本，不能选旧的、不能回退。组件包有自己的发行版本，现在跑的是哪个版本查得到，这是另一回事。
- 没有“从平台导出再导入”，也没有一键恢复。
- 不把面板放进隔离框运行，也没有代码批准这一步。隔离的能力留着，以后要运行不受信任的代码时再看。
- 面板的 CSS 可以用固定定位把东西画到面板外面，也可以引用外部地址。现阶段不处理：已定人人都能写 HTML 和 CSS、不按受不受信任区分，底线只用最小的办法守；等以后有不受信任的作者（对外开放）时再看。

## 六、平台现在做到哪了（2026-11-20）

标准是目标，平台正在分批实现。下表说的是“现在照着写，能不能在平台上跑起来”。

| 标准里的 | 现在 |
| --- | --- |
| Vue 面板直接运行 | 平台正在接入直挂。数据和操作使用目标部署已登记的属主声明 |
| 面板放进面板、对列表重复、位置由状态决定 | 在做 |
| 状态按人保存、对外；入口给面板传值；外框面板 | 在做 |
| 检查命令、登记命令和配套的构建技能 | 从 App Builder 技术指南开始，按检查、登记、打开入口的顺序做 |
