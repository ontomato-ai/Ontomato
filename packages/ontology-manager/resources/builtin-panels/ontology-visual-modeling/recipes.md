# 可视化建模页的常见做法

这一页在平台的共用图谱画布上编辑本域的对象类型（点）、关系类型（边）和它们下面的属性：拖动布局、按住 Shift 从一个类拖到另一个类建关系、选中后编辑或删除。

## 看页面上是什么

- 画布上是本域的全部对象类型和关系类型，节点和边都写属主给的名字，不是内码。
- `selectedNode` 是选中的对象类型（主键是类的 API 名），`selectedEdge` 是选中的关系类型（主键是关系名）；点画布空白处两个都清空。地址里带 `state={"selectedNode":{"className":"platform:ObjectType","primaryKey":"<类>"}}` 就是直接打开并选中那个类。
- `className` 跟着 `selectedNode` 走，属性列表（`attributes` 的 `rows`）就是它的属性；`selectedAttribute` 指向其中一条。
- `dialog` 是页面开着的对话框：`class`（新建对象类型）、`relation`（新建关系类型），页头两个命令打开的就是它。
- 回答“现在选了什么、在改什么”时，先看这几个状态，再用上面两个读取取当前字段，不要凭记忆。

## 起草表单（读者保存后才写入）

起草前先读属主表单（类的 `classForm`/`classCreate`、关系的 `relationForm`/`relationCreate`、属性的 `attributeForm`），`operation` 用它返回的 `save.draftOperation`，`form` 里只放要改的字段。草稿怎么写（草稿信封、链接参数）见本页生成的技能。把草稿链接交给读者，由读者在表单里检查并保存；不要替读者保存。

- 改类：只有显示名和说明可改，API 名只读。
- 新建类：字段是 API 名、主键名、显示名、业务描述；格式和重名由属主校验，原因显示在字段旁。
- 改关系：两端对象和关系名只读，可改两个关联字段和说明；关联字段从两端对象的属性里选，换了任一端要再问一次表单拿新选项。
- 新建关系：关系名、两端对象、两个关联字段、说明都由属主给；两端也可以先在画布上按住 Shift 拖出来，页面会预填进这张表单。
- 改属性：可改显示名、说明、启用、业务键；属性名、数据类型、所属类只读。

## 需要确认才执行的操作

- 删除对象类型 `classDelete`：会连同两端任一是它的关系一起删掉。执行前先读画布上的边，点名会被一起删掉的关系；经读者确认后执行。
- 删除关系类型 `relationDelete`、删除属性 `attributeDelete`：都要读者确认。设主键用 `attributePrimaryKey`；已是主键的属性不要再设。
- 属主拒绝时把它给的原因原样转告读者，不要换别的办法绕过去。

## 跳转

- 选中一个类时可以“浏览数据”：打开 `/browser/data/<类的 API 名>`。
- 本体图谱页 `/ontology/playground` 选中某个类后“去建模”会带着它打开本页（地址里 `state` 带 `selectedNode`）。
