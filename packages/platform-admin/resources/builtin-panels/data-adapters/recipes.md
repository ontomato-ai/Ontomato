# Data adapters

- Use `adapterForm` to choose the domain's active data adapter mode (a single installed adapter or multi-source routing) and edit its connection fields. Secret fields are never echoed back from the server; leave a saved secret blank to keep the stored value, or type a new value to replace it.
- In multi-source mode, define each data source (with its ID, adapter type, and adapter-specific connection fields) in `adapterForm`. Ontology class and relationship routing are lazy-loaded in the separate `routingForm` projection only in multi-source mode, so an ontology outline read failure stays isolated with its own retry button and never blocks editing data sources or testing connections.
- Use `testConnection` to test the current unsaved single-source draft below the form, or click **Test connection** inside any multi-source data source card to test that source independently without saving or switching the domain adapter. Results render inline in a structured report and clear automatically when the tested draft changes.
- The **Action trial & sandbox permission** section reads the saved result without probing. For an unchecked or failed writable source, use **Check permission** to refresh the result. This operation, a writable connection test, and a save check permissions by creating and immediately deleting one empty probe table or equivalent object in the business data source. A read-only source does not support write actions and creates no probe object.
- A save can succeed even when permission checking fails. In that case the save receipt explains why actions cannot be trialed or published until create/drop permission is granted.
