## 已实现

- 产品目录按“被组合元素 / 组合形态 / 智能组合应用”分层。四类投影属于元素，Page 与 Navigation 属于组合形态，Application 与 AgentProfile 属于应用；布局模板继续使用 `Page.isTemplate`。创建菜单只提供这八类，存量兼容资产仍可通过原 ID 访问和迁移。
- `/types` 和普通 HTTP 保存只提供八类 authoring 契约，Page 不接受 workspace。历史解析和显式迁移保留旧输入；旧资产详情标记兼容状态并要求迁移后编辑，新发布拒绝旧类型进入快照。
- 依赖接口同时返回有向图，保留组合中间节点以及 contains、navigates、tools、context、renders、embodies 关系。详情按层显示可跳转的引用图。四类投影与 Bundle 身份由 Java 本体侧登记，renders / embodies 由本体侧关系表持有，Page / Navigation 组合引用仍从产品配置派生。Node 使用同事务 outbox 同步登记，失败保留重试；投影发现读取本体登记，不再读取原 Node renders 索引。
- 目录提供当前主体可见资产的完整引用图，以及按可见已发布 ObjectType / Definition / MetricView / Action 扫描默认投影的警告检查。检查不自动创建投影，不把不可见默认投影视为可消费面孔。
- Page 保存及启动迁移将旧 workspace 提取到作者的 Principal overlay，持久化 Page 和新发布快照移除 workspace；个人资源选择不再派生为 Page 的发布依赖。历史发布记录保持原值。
- 新建个人主页直接生成 Page 与平台 Definition/CollectionView，不再生成旧平台 widget；问数区域引用当前主体可用的已发布 Profile，缺少可用 Profile 时保留可配置 Page 并提示选择。已有主页保持显式迁移，避免丢失固定会话、Agent 快捷入口和仪表盘内部配置。
- 保存和发布检查 Page 变量绑定与能力参数的类型兼容，子 Page 检查同名参数的本体类型；修改共享投影时重新检查直接父 Page。发布 Navigation 限制页面转场范围，SDK 支持打开指定 ObjectView 的类型化实例。
- 无源码工作区的声明式 Application 使用与 AgentProfile 相同的发布记录和回滚机制，通过活动快照运行 Navigation 和页面；发布和回滚同步平台目录的 product 应用身份与入口，沿用同一 use/edit Grant。源码应用仍由工作区发布机制管理。
- 声明式 Bundle 提供升级差异预览，比较活动发布与当前引用树的子资产修订及能力契约；预览不修改发布，显式发布才更新活动版本。
- 发布记录读取拒绝缺失子资产、能力契约与重复身份；新契约版本纳入 Definition 的对象输出 schema 及 ObjectType 关系端点，并规范化字段顺序。历史契约按原版本校验，避免升级代码直接使旧发布失效。
- 新源码发布在 Java Function 仓登记 `OPERATION_PRODUCT` 制品，按域、应用和发布生成确定性身份，记录构建派生文件哈希、SDK 版本与冻结能力契约。制品不可原位替换，不能进入 Python 能力执行器，发布后由历史记录保留。目录身份与制品身份分别承担应用访问和交付追溯。
- Agent 上下文允许引用声明字段的 `3d` ObjectView，与 `text` 变体使用相同的服务端字段装配边界。
- Profile 会话保存页面参数的标量或对象身份引用，工具回调以 sessionId 读取当前发起人拥有且绑定同一 Profile 发布的状态；非 literal 工具绑定据此解析，Action 的只读绑定仍不可覆盖。Page 组合校验涵盖嵌入 Profile 的工具参数，能力签名类型检查复用页面绑定校验。
- AgentProfile 以 `agentId` 引用同域 Node 智能体定义；执行身份从该定义当前的 `executionUserId` 解析。旧独立主体、角色赋权和额外 agent use 已退役；产品资产的 use/edit、冻结指令/工具/上下文继续保留。此处只陈述集成分支代码，128 上的新身份组合验收尚未完成。

- `widget-group` 和 `operation-panel` 转为 `page`，内联单元提取为独立资产，原根 ID 保留。子 ID 按父 ID 与原组件 ID 确定性生成，重试不产生新树。
- 纯展示组设置 `embeddable`，模板转为 `page.isTemplate`。操作组合保持普通 Page，多操作不构成事务。
- Page 可引用子 Page；保存使用候选根检查间接循环。`embeddable` 限制递归生效，不能通过子 Page 引入 Action。
- 页面引用增加 1–12 列 `width`，迁移保留原内联组件跨度。现有 `span` 继续兼容。
- 新建菜单移除组件组、操作板和布局模板，旧输入仍通过保存边界转换。数据库启动迁移保留原资产身份和引用。
- `product_asset_revisions` 保存资产修订；`product_releases` 保存源码发布的递归资产快照、根引用及 MetricView / Action 契约哈希。
- 发布时校验并捕获引用树；同一源码提交重复发布沿用原发布记录。共享资产编辑不会改变该发布快照。
- SDK 嵌入通过注册的应用身份请求活动发布中的资产，Page 的子项继续从同一快照解析，不读取最新定义替代。
- 回滚读取目标发布的快照根；权限仍按当前访问者判断，能力契约变化明确返回 `PRODUCT_CONTRACT_CHANGED`，没有快照的历史发布返回 `PRODUCT_RELEASE_UNPINNED`。
- 发布引用的资产不允许删除。编辑修订与发布修订不共享权限结论。

## 当前限制

已增加 MetricWidget / ActionView 独立投影契约及旧能力 widget 转换；CollectionView 通过独立 Definition 签名查询成员。Definition 暂在 Node 独立表保存，已发布定义禁止原位修改。Navigation 与 AgentProfile 有引用校验；Profile 已支持发布快照、活动版本和回滚，Agent 准备阶段装配活动快照。Profile 工具描述尚不构成执行授权或完整工具调用闭环。

Profile 提供冻结工具执行入口 `POST /api/product-assets/:id/tools/:toolId`：工具必须存在于活动发布的工具面，执行时沿用当前主体的治理接口，Action 的只读参数不能覆盖。工具入口不构成独立权限来源。

运行器接收 Profile 工具 schema 并按绑定发布装配冻结工具树；回调凭据仍限定 run、期限和工具路径。发起人负责产品访问与会话归属，业务工具使用本轮固定执行用户及 Java 当前权限。指定用户 Key 不进入模型环境；旧主体短期令牌路径已删除。

主体退役前的历史本地演示曾验证只读 Profile 工具返回 count=20；它不证明本次执行用户模式的真实结果。新格式 Profile、Action、CollectionView、对象上下文及双身份组合仍须在 128 按第 12.8 节重新验收。
